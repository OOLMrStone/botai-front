# Архитектура геометрии

## Цель

Случайный локальный радиус или размер контрола должен ломать проверку до просмотра браузера. Спецификация визуальных ролей: [work-3-design-system.md](work-3-design-system.md). Проверка: `npm run test:design`, автоматически входит в `npm run lint`; новых зависимостей нет, используется установленный TypeScript.

## Единственный путь изменения

1. Выбрать существующую роль в `src/config/layout.ts`
2. Отдать компоненту ссылку на роль; Button получает семантический `size`
3. Новая роль допустима вместе с контрактом размера, всеми потребителями и проверкой в браузере

Численные источники радиусов находятся в `src/app/globals.css`: control, tile, card, panel. Конфиги используют семантические классы, круг или производный радиус. Одинаковый DOM-тег не означает одинаковую форму: Button с ролью card остаётся карточкой.

`layout.control.sizes` - закрытый публичный набор: default, multiline, compact, icon, icon-compact, card, segment. Роль multiline сохраняет капсулу и минимум 48 px при обычном размере текста, растёт по содержимому и переносит подпись; она применяется к текстовым действиям billing, включая повтор запроса и подтверждение отмены. Default и icon остаются фиксированными. Добавление ключа или уменьшение области нажатия роняет тест. Геометрия Button и Input применяется после внешнего className; объединение Tailwind-классов знает семантические радиусы. Внешний className не должен перебивать геометрию роли: это проверяется вызовом настоящих примитивов с конфликтующими классами и настоящим объединением Tailwind-классов.

## Что блокирует guard

- `rounded-*`, включая семантический радиус, внутри app/components: view должен читать роль целиком
- Локальные h/w/size/min/max dimensions, радиусы и размер шрифта у Button, Input, ValidatedInput, ValidatedField и нативных button/input
- Те же значения через `cn`, условие, template literal, локальную переменную/функцию, alias импорта, объект props, вызов buttonVariants
- Inline style с height/width/min/max dimensions/fontSize/borderRadius у контролов; borderRadius во всех view
- Непрозрачный spread на контроле, кроме перечисленных инфраструктурных передач props
- Несемантические rounded в config; `calc`, `max`, `min` допустимы только со ссылкой на семантический радиус
- Дублирование источника семантического радиуса, нарушение численного контракта, новый размер Button без контракта

AST разбирает JSX и выражения. Проверка не зависит от форматирования или наличия ожидаемой строки кода. Собственные положительные и отрицательные fixtures доказывают, что guard различает разрешённую композицию и обход. Runtime-тесты отдельно проверяют поведение реальных Button и Input.

## Точные исключения

| Место | Исключение | Причина |
| --- | --- | --- |
| ui/button.tsx, ui/input.tsx | Геометрия при реализации примитива | Это владельцы API, не экранные потребители; радиусы по-прежнему запрещены локально |
| ui/progress.tsx, ui/radio-group.tsx | Только rounded-full | Круглая форма внутреннего индикатора |
| ui/skeleton.tsx | Только rounded-md | Низкоуровневая заглушка; формы экранных skeleton задаёт config |
| onboarding/ValidatedField.tsx, ui/validated-input.tsx | Только spread props | Типизированный проход атрибутов поля; геометрия проверяется у вызывающей стороны |
| ui/dialog.tsx | Только spread handleProps | Обработчики жеста из общего hook |
| dev/DevTools.tsx | Локальная геометрия | Вспомогательный инструмент разработки вне пользовательского интерфейса |

Список закрытый и поимённый. Новая папка ui или компонент автоматически исключение не получает. Добавлять исключение ради прохождения теста нельзя: сначала подобрать роль или исправить примитив.

## Границы проверки

Это архитектурный guard, не проверка качества изображения и не защита от намеренного переписывания тестов. Анализ локальных выражений не заменяет полный анализ произвольного JavaScript между модулями. Геометрию из неизвестного внешнего helper, новый CSS-механизм или новый обёрточный компонент нужно включать в контракт при добавлении.

Тест классов не доказывает пиксельное выравнивание. `scripts/check-design-geometry.mjs` измеряет реальные прямоугольники и эффективные радиусы в браузере; перенос текста, safe-area, изменение размера текста, клавиатуру и движение проверяют в preview. Обе проверки обязательны при изменении UI.

## Red перед исправлением

На первой содержательной проверке 29 сентября 2026 guard обнаружил 20 нарушений: локальную геометрию на входе и регистрации, три несемантических радиуса config. После миграции эти нарушения исчезли. Runtime-проверка затем выявила отдельную ошибку: Tailwind merge сохранял rounded-none рядом с rounded-control, потому что новый токен ещё не входил в известную ему группу конфликтов. После регистрации семантических радиусов в общем объединении классов runtime-проверка проходит. Это падение проверяет реальное поведение, а не структуру реализации.

## Защита типографики

`test-typography.mjs` входит в test:design: один локальный Onest Variable с кириллицей и латиницей, один tracking-токен, запрет локальных tracking/font-family/letter-spacing и fieldset/legend вне FormSection. Отрицательные fixtures проверяют обычные обходы через классы и inline style. Как и геометрический guard, это ограничение архитектуры, не доказательство качества кернинга или универсальный анализ произвольного кода. Живой браузерный замер дополняет его; контракт: `work-3-typography.md`.
