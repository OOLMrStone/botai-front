# Лемур: каталог сценариев и анимаций

Срез существующего фронта: 29 сентября 2026 года. Это спецификация самостоятельных ассетов, без интеграции в приложение. Приоритет P0 означает прямой запрос пользователя; P1 закрывает подтверждённый дополнительный сценарий; P2 относится к будущему. Длительности ниже - рекомендации для производства и просмотра, не требования к продуктовым таймерам.

## Что уже существует

- Приветствие `src/app/onboarding/intro/page.tsx` использует общий `ResultScreen` и `MascotPlaceholder`. На `welcome` сейчас сфера из частиц; замена сферы не входит в эту работу
- Главная `src/app/(app)/home/page.tsx` содержит приветствие, стрик, XP и дневную цель. Сам маскот и реакция на тап пока отсутствуют
- `src/components/onboarding/BuildingLoader.tsx` показывает плейсхолдер маскота во время построения курса; `src/hooks/use-mock-exam-check.ts` предоставляет реальное состояние `checking` для проверки пробника
- `src/app/streak/page.tsx` уже показывает награду после вводного урока, хотя `src/app/lesson/page.tsx` остаётся заглушкой
- `src/config/quiz-engine.ts` задаёт `feedback: correct | incorrect | null`; `src/components/quizzes/QuizResult.tsx` различает идеальный и неполный результат. Это две разные эмоциональные ситуации
- `src/components/onboarding/ResultScreen.tsx` повторно используется в `intro`, `level-result`, `daily-goal-result`, `ready` и `register/done`; `register/save-progress` напрямую использует плейсхолдер
- `src/components/tasks/TrainingExitDialog.tsx` предлагает оставить или убрать решённые задачи из избранного. Это **не** подтверждение потери прогресса. Выход из квиза сейчас сразу вызывает `exit` в `src/components/quizzes/QuizExperience.tsx`
- Счётчик последовательных правильных ответов в состоянии квиза отсутствует. Всплывание за серию - запрос пользователя на ассет, но ещё не действующий сценарий
- Иконка сайта существует как `src/app/favicon.ico`. Замена иконки не входит в производство ассетов

## Основной набор

| ID | Приоритет | Сценарий и подтверждение | Постановка движения | Режим / длительность |
| --- | --- | --- | --- | --- |
| `neutral` | P0 | Каноническая модель для всех состояний | Стоит или сидит, улыбка, хвост с неизменным чёрным кончиком | Статичный прозрачный ассет |
| `wave` | P0 | Приветствие `onboarding/intro`; запрос пользователя | Взгляд на зрителя, короткая подготовка, два взмаха одной лапкой, возврат | Один раз, 1,8-2,4 с; затем `idle` |
| `idle` | P0 | Будущий маскот главной `home`; базовый вид ResultScreen | Спокойное дыхание, небольшое движение хвоста, редкое моргание; длительная пауза | Бесшовный цикл 5-7 с |
| `heart` | P0 | Тап по маскоту главной, по запросу пользователя | Лапки к щёкам или груди, одно сердечко вылетает вверх, улыбка, возврат | Один раз, 1,5-2 с |
| `walk-right` | P0 | `BuildingLoader`; возможное повторное использование при `checking` пробника | Четвероногая походка вправо на месте, выразительный крупный зад, хвост вверх; голова и глаза того же персонажа | Бесшовный шаговый цикл 1-1,4 с |
| `cry` | P0 | Прямой запрос пользователя; подтверждённого экрана потери прогресса сейчас нет | Приседает, уши слегка опускаются, глаза наполняются слезами; мягкая грусть без истерики | Вход 0,5-0,7 с и спокойный цикл 2,5-3,5 с |
| `celebrate` | P0 | Успешный конец урока; идеальный результат `QuizResult` | Подготовка приседом, прыжок, раскрытые лапы, мягкое приземление; немного конфетти | Один раз, 2-2,6 с; затем `idle` |
| `streak-pop` | P0 | Награда `streak`; будущая серия правильных ответов | Быстро выглядывает снизу, радостный жест, короткая читаемая задержка, уходит | Один раз, 1,2-1,8 с |
| `icon-static` | P0 | Иконка сайта и возможного приложения | Крупная голова, большие оранжевые глаза, нос и рот между ними; минимум деталей | SVG/PNG и варианты малых размеров |
| `icon-blink` | P0 | Прямой запрос на анимацию иконки | Один blink и еле заметный наклон; лицо не покидает безопасную область | Один раз, 1-1,4 с; отдельный ассет превью |
| `correct` | P1 | `feedback === correct` в квизах; статусы правильных задач тренировки | Короткий кивок или один небольшой подскок, без большого праздника | Один раз, 0,65-0,9 с |
| `encourage` | P1 | `feedback === incorrect`; неполный результат квиза; низкий `levelBand` на `level-result` | Поддерживающий наклон головы, затем улыбка и протянутая лапка | Один раз, 1,2-1,7 с |
| `proud` | P1 | `daily-goal-result`, `ready`, `register/done`, высокий `levelBand` | Выпрямляется, лапки на груди или боках, довольная улыбка | Один раз, 1,3-1,8 с; затем спокойная поза |

Минимально полный набор состоит из 13 состояний, из них десять напрямую запрошены. `cry` не стоит автоматически привязывать к ошибке в задании: текущие тексты результата поддерживают ученика. `encourage` сохраняет этот смысл. `icon-blink` не обещает анимацию системной иконки браузера или приложения: платформенная интеграция требует отдельного решения, статичная версия обязательна.

## Разумные будущие состояния

| ID | Приоритет | Когда пригодится | Режим / длительность |
| --- | --- | --- | --- |
| `think` | P2 | Осмысленное ожидание ответа или подсказки, если такой экран появится | Цикл 3-4 с, лапка у подбородка |
| `peek-left` / `peek-right` | P2 | Маленькая реакция сбоку экрана после серии заданий | Один раз 1-1,5 с; общая пластика со `streak-pop` |
| `sleep` / `wake` | P2 | Возвращение после бездействия, если будет согласован сценарий | Сон 5-7 с; пробуждение 1,2-1,6 с |
| `confused` | P2 | Пустое состояние или недоступные данные, если там нужен маскот | Один раз 1,3-1,8 с; без паники |
| `goal-reached` | P2 | Достижение дневной цели по данным статистики | Один раз 1,5-2 с; можно переиспользовать `proud` |
| `dance` | P2 | Особая награда, крупный стрик, праздничная коммуникация | Цикл 2,5-3,5 с; не фоновый idle |

Не создавать отдельные вариации без нового смысла. `correct` и `celebrate` нужны оба из-за разного масштаба события; отдельные праздники для регистрации, цели и каждого предмета пока не нужны.

## Общий контракт ассетов

- Один исходный дизайн и одна палитра для всех ракурсов и эмоций; число полос и чёрный кончик хвоста не меняются
- Резкий прыжок между анатомией сидящего персонажа и шагающего недопустим: для ходьбы меняется ракурс и поза, сохраняются большие глаза, маска лица, уши, хвост и пропорции узнаваемых деталей
- Взмах, сердце, кивок и празднование начинаются и завершаются совместимой нейтральной позой. Повторный тап не наслаивает эффекты и не обрезает важный жест
- Ходьба направлена вправо; вариант на месте пригоден для загрузчика, реальное перемещение по экрану - отдельная задача интеграции
- Основной ассет имеет прозрачность и отдельную простую тень-полоску. Проверка на белом, тёмном и цветовом фоне
- Тихая версия reduced motion: выразительная статичная поза вместо цикла. Она нужна для каждого состояния, а не только idle
- Зафиксировать безопасную область, точку опоры лап и полный размах хвоста; он не должен обрезаться при движении
- Экспорт превью GIF/MP4 служит просмотру. Рабочий формат выбирается после исследования реальной технологии референсов и воспроизводимости качества, а не из предположения, что Duolingo использует GIF
- Анимации проверяются в движении целиком: читаемость жеста, дуги, паузы, отсутствие скольжения лап, бесшовность, сохранение лица. Контактный лист сам по себе не доказывает качество движения

## Границы этой работы

Исходный код и интеграция не меняются. SCOPE.md описывает действующее приложение и пока сохраняет маскота вне scope. Настоящий каталог описывает будущие ассеты и явно отделяет существующие состояния от новых продуктовых сценариев. Проектные skills просмотрены по описаниям; изменения экранов, компонентов, типографики и кода в этой исследовательской подзадаче не выполнялись.
