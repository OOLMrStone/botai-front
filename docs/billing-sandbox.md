# Тестовая оплата, 8 октября 2026

Статус: V14 frontend реализован после security gate: месячная подписка с автопродлением и разовый сезонный пакет. Источник API - компактный backend-контракт; реальные provider checkout и recurring E2E проверяются отдельно по разрешению root. Предыдущий static visual PASS относится к V13, новый visual review требуется для подписки.

Изолированные `/billing/sandbox` и `/billing/return?paymentId=<UUID>` используют backend-контракт `botai-back/docs/integration/YOOKASSA-TESTING.md`. Публичные кнопки покупки остаются отключёнными. Frontend не выбирает платёжный режим по `APP_ENV` и не хранит ключи магазина.

После входа предложения и доступ загружаются с `/api/billing/offers` и `/api/billing/status`. Экран открывает покупку только при `mode=test` и `testOnly=true`. Каталог сервера задаёт цену, квоту, длительность или абсолютный конец; UI использует прежние названия пакетов. Месячный offer имеет kind=subscription, сезонный - one_time. UI не подставляет клиентские цены и не меняет публичные кнопки покупки. Поле `currentPaymentId` восстанавливает незавершённую операцию после потери sessionStorage или в другой вкладке, без нового POST создания.

До создания платежа или подписки вкладка сохраняет UUID `Idempotency-Key`, offerId, immutable offer и принятое согласие отдельно для каждого аккаунта. POST `/api/billing/subscriptions` получает только offerId и consent {accepted:true,version}; сезон использует POST `/api/billing/payments`. Ошибки recurring_consent_required/changed гарантированно происходят до создания операции: только при них локальная попытка очищается и согласие запрашивается заново. Потеря ответа и перезагрузка сохраняют ключ. Неопределённая попытка не позволяет сменить предложение. Локальный id сохраняется до перехода на проверенный HTTPS confirmation URL. Поля карты находятся только на странице ЮKassa.

Return URL ничего не подтверждает: экран получает локальный статус, затем последовательно вызывает refresh не чаще одного раза в 5 секунд, максимум 12 проверок за цикл. Скрытая вкладка не опрашивает сервер. Доступ показан только для test payment со статусом succeeded и entitlementApplied=true; кэш профиля обновляется с сервера. Pending, timeout, waiting_for_capture и review_required не дают доступ. Отмена платежа означает только подтверждённый canceled; новая попытка получает новый ключ и доступна лишь при server canPurchase=true. Ранее оплаченный период сохраняется независимо от результата продления. Закрытие страницы и возврат назад не отменяют платёж.

В профиле появляется ссылка «Твой тариф · Тестовый режим» только после mode=test/testOnly=true; disabled, live, ошибка или смена владельца скрывают её. Тот же единственный результат status на странице профиля скрывает старую карточку основного тарифа только в test-mode, чтобы оплаченный sandbox-доступ не соседствовал с «Бесплатный». Основной plan пользователя не меняется; вне test-mode карточка сохранена. Return после успеха тоже ведёт к управлению. При истёкшей сессии общий вход сохраняет только разрешённый billing-маршрут в sessionStorage. Произвольные адреса и неподтверждённые параметры результата отбрасываются. Проверка владельца и допуска к sandbox остаётся обязанностью backend.

Node-тест `scripts/test-billing.mjs` проверяет idempotency после потери ответа, изоляцию аккаунтов, запрет смены предложения, canceled/new-key, отказ при недоступном хранилище, fail-closed для live-ответа, redirect allowlist, auth return и HTTP boundary. Browser QA и реальный тестовый checkout отмечаются отдельно: успешный mock не доказывает связь с ЮKassa.

После UX-review выбор использует общий `BillingPeriodSwitch`: месяц/сезон и три серверных предложения. На телефоне сначала выбранный тариф, остальные раскрываются действием «Другие тарифы»; на desktop видны все три. Выбор обозначен кольцом с галочкой и доступным keyboard focus. При незавершённой покупке показывается одна сводка вместо отключённой сетки.

`Payment.offer` - обязательный неизменяемый snapshot заказа из backend. Единый `BillingOfferSummary` показывает имя тарифа, полную цену, число проверок и срок в выборе и на странице результата для pending/canceled/succeeded/review_required. Карточки не используют клиентские цены витрины. «Тестовый режим» вынесен в компактную отметку шапки; рядом с заголовком остаётся «Без списания реальных денег», разовость или периодичность стоят рядом с ценой и сроком.

Действия находятся в отдельном непрозрачном footer рядом с прокручиваемым main; ширина фона не ограничена шириной CTA. В коротком горизонтальном окне прокручивается вся оболочка, main и footer идут в обычном потоке. Сезонный срок отображает последний доступный день по Москве включительно, вычисленный из исключительной границы backend; сама граница не меняется.

## Подписка и сезонный пакет

Сохраняем текущую визуальную систему, общий переключатель месяца/сезона, карточки, summary и исправленную структуру прокрутки. Месяц становится подпиской; сезон остаётся одной покупкой со всей квотой сразу и сроком по 10 июня 2027 включительно. Данные обоих предложений берутся из API. Legacy `*-month-v1` остаются разовыми сохранёнными попытками; новый subscription offerId не подменяет их смысл.

Перед подключением месяца показываем компактное резюме: сумма сейчас, последующая сумма каждые 30 дней, квота нового периода. Отдельный checkbox согласия изначально снят и расположен в прокручиваемом содержимом над CTA. Текст включает сумму, периодичность и фактическое место отключения в «Твоём тарифе». CTA «Подключить подписку» доступен после явного согласия. Пока checkbox снят, рядом с отключённой CTA показано текстовое действие «Чтобы подключить подписку, подтверди согласие»: оно мгновенно прокручивает main к checkbox и ставит фокус, ничего не отмечая и не отправляя. После согласия подсказка исчезает. Смена предложения сбрасывает согласие; повтор уже созданной попытки сохраняет исходные ключ, предложение и принятую редакцию. Для сезонного пакета checkbox автопродления отсутствует.

После первой подтверждённой оплаты точную дату следующего списания показывает backend. До неё UI сообщает периодичность, без вычисления даты от клиентского времени. У действующего продукта каталог заменён одним блоком «Твой тариф»: остаток проверок, оплаченный срок по Москве, отдельное состояние автопродления. Следующая сумма и дата видны только при подтверждённом `renewalEnabled=true`. Одновременно действует один продукт; доплаты, пополнения, совмещение и смена тарифа в этом этапе не обещаются.

До первой оплаты pending_initial допускает отзыв согласия, хотя renewalEnabled ещё false; поздний успех даст доступ без автопродления. Отключение автопродления - одно действие и одно короткое подтверждение с датой сохранения оплаченного доступа, без удерживающих предложений. После запроса кнопка показывает ожидание; успех или сбой определяет сервер. При сбое UI не меняет состояние подписки. Фокус возвращается на исходное действие после закрытия подтверждения. Закрытие страницы и «К подготовке» не отменяют платёж или подписку.

| Подтверждённое состояние | Что видит пользователь и что может сделать |
| --- | --- |
| Первая оплата прошла, способ сохранён | «Оплата прошла», оплаченная квота/срок, автопродление включено, точная следующая сумма и дата |
| Первая оплата прошла, способ не сохранён | «Оплата прошла», «Автопродление не подключено», оплаченный доступ сохранён; кнопки повторной покупки нет |
| Оплата ещё не завершена | Сводка исходной покупки и проверка результата; переход к оплате только при допустимом confirmation URL |
| Продление отклонено | «Не удалось продлить», «Повторного автоматического списания по этой попытке не будет»; оплаченный доступ показывается отдельно, новая покупка только при `canPurchase=true` |
| Автопродление отключено, платежа в обработке нет | «Автопродление отключено», оплаченный доступ до точной даты; следующего списания не обещаем |
| Отключение подтверждено, последний платёж уже отправлен | «Автопродление отключено. Последний платёж уже отправлен, ожидаем результат. Он ещё может завершиться списанием»; сумма этого платежа и проверка результата. Его итог не включит автопродление обратно |
| Неизвестный результат отключения или оплаты | Сохраняем последнее подтверждённое состояние, предлагаем проверить снова; не объявляем отмену/успех и не создаём новую попытку |
| Нужна ручная проверка | Нет нового checkout и обещания доступа; остаются проверка результата и выход к подготовке |

## Контракт и проверка

DTO и цены находятся в `botai-back/docs/integration/YOOKASSA-TESTING.md`; этот документ не дублирует их. Сумма всех продлений совпадает с immutable offer.amount. `nextPaymentAt` и `paidThrough` приходят с сервера; `checksRemaining` учитывает `checksReserved`. `inFlightPaymentId` ведёт к существующему Payment GET/refresh. Назначения платежа: `one_time`, `subscription_initial`, `subscription_renewal`. Legacy разовые месячные операции продолжаются с исходным ключом, даже если их предложение уже исчезло из каталога.

После подтверждённого отключения UI не включает автопродление по позднему успеху: принимает состояние только из Subscription. На server failure подтверждённое состояние не меняется. Ответ после ухода со страницы или смены аккаунта не меняет экран и не перенаправляет пользователя.

`scripts/test-billing*.mjs` проверяют прежний redirect/return/poll/ownership и новые consent/reset/reload, immutable replay после смены каталога, definitive consent errors, отсутствие overlap, отмену с in-flight и при timeout, pending_initial revoke, saved=false, decline без autoretry, server dates и fail-closed ссылку профиля. SSR fixtures содержат только тестовые данные компонентов, без обращений к API/ЮKassa и без публичного mock-route. Live hydration/keyboard/focus и provider checkout отмечаются отдельными доказательствами; unit/SSR не заменяют их.

## Дополнительная проверка доступности и сети

Root подтвердил hydrated UI на 320×640 и 375×812: footer-подсказка прокручивает к настоящему checkbox, сохраняет checked=false и не создаёт платёж; переполнения нет. В финальном профиле оплаченного тестового аккаунта осталась одна ссылка управления без старой карточки «Бесплатный». Переходы sandbox → profile → settings → logout → billing/login и console warn/error проверены root без замечаний. Это результаты браузерной эмуляции, не гарантия для всех физических Android.

Все запросы общего API имеют timeout 10 секунд с abort, включая CSRF bootstrap. Опрос оплаты последовательный, ограничен 12 попытками и останавливается при ошибке/скрытой вкладке; отмена и создание возвращают доступность действий после сетевого сбоя. Неизвестное создание повторяется с исходным ключом. Ошибка обновления уже оплаченного управления показана через ErrorNote с retry, сохранением последнего подтверждённого доступа и автопродления; retry читает статус и не создаёт платёж.

Независимый reviewer проверяет footer/нижнюю навигацию, последний элемент scroll, loading/error/retry, consent и modal focus на 320×480/640, 360×640, 375×667/812, 412×732, 640×360/812×375 и широком desktop. Измеренные дефекты устранены без изменения платёжного контракта. Повторная проверка кандидата подтвердила:

- Тренировка 320×480 и 375×812: условие читаемо, весь раскрытый разбор доступен общей прокруткой, нижние действия достижимы. Жест переходит от рабочей области карточки к main без scroll-ловушки
- Главная 812×375 и 1280×720: название, дата и действие результата читаемы; горизонтальная раскладка выбирается по ширине колонки
- Login/settings 360×300: поля и действия достижимы прокруткой. Это proxy короткой доступной высоты, не проверка настоящей экранной клавиатуры; данные не менялись
- Финальный synthetic 200% root font/rem на 320×640: структура шапки/main/footer и все действия доступны, подписи переносятся целыми словами. Текстовые действия, включая ошибку и отмену, используют multiline-роль

Финальный targeted visual recheck пройден, console без ошибок. Root подтвердил реальный network error/retry на финальном образе, 360×640: при остановленном backend обновление статуса показывает ErrorNote и «Повторить», сохраняя 69 из 70 проверок, оплаченный срок и отключённое автопродление. После восстановления backend повтор убирает ошибку, сохраняет квоту и не создаёт новый платёж. Физический Android, IME, OS text scale и CPU/FPS этим проходом не измерялись. Эмуляция размеров и synthetic stress не доказывают работу на всех физических устройствах. Скриншоты и runtime fixtures сохраняются отдельно от Git.
