# Work 3: единая геометрия botai

Статус: контракт Work 3, 29 сентября 2026

## Задача и диагноз

Ученик должен видеть условие, вводить ответ и двигаться дальше без сомнений. Порядок внимания: условие → ответ/прикрепление → навигация и прогресс. Сохраняем монохромную основу, цвет только для результата, крупную русскую типографику, свободное пространство, общий Button, ScreenHeading, ScreenShell, локальную защиту жестов, клавиатурную адаптацию и config/layout.ts.

Разрыв системы: Button задаёт маленький радиус, соседняя стрелка переопределяет его, поле имеет третий; длинная подпись последнего задания увеличивает высоту только части строки. Прогресс онбординга не резервирует место справа. Короткий ответ принимает произвольный текст. Статус пробника меняется до навигации без обратной связи; многоклик требует проверки в браузере.

Идея: **мягкие действия, спокойные поверхности**. Форма выражает роль, а не принадлежность экрану. Не меняем палитру, бренд и структуру учебных сценариев ради нового оформления.

## Что заимствуем

- Dodo, пользовательские IMG_8163–8167: полукруглые торцы действий, круг для отдельной иконки, отдельное семейство карточек и шторок. Кнопки одной строки равновысокие. Не переносим оранжевый бренд, рекламную плотность и иллюстрации еды
- [Apple HIG: Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons): форма зависит от роли и контекста; круг у иконок, капсула у действий. HIG не требует одного радиуса для всех элементов
- [Apple: UI Design Tips](https://developer.apple.com/design/tips/): ясное выравнивание, удобная область нажатия. Для нашего web-интерфейса принимаем минимум 44 CSS px как собственный контракт, не равенство физических pt и px
- [Revolut 10](https://www.revolut.com/blog/post/revolut-10/): быстрый доступ к основному действию, ясная иерархия. Это опубликованный разбор версии 2023 года, не аудит текущего приложения
- [Drinkit](https://guest.drinkit.ru/ru): персонализация внутри понятного сценария заказа. Для botai это постепенное раскрытие настроек. Точные радиусы Drinkit не измерены и не используются как доказательство

## Геометрический контракт

| Роль | Правило | Обоснование |
| --- | --- | --- |
| Действие, фильтр, однострочное поле | Капсула, эффективный R = min(width, height)/2 | Одинаковые торцы при разной ширине |
| Иконка действия | Круг, ширина = высота, минимум 44 | Та же капсула в квадрате |
| Карточка контента/выбора | R = 24 | Текстовая поверхность не должна выглядеть огромной кнопкой |
| Большое рабочее поле, шторка | R = 32 | Крупная поверхность, отдельная глубина |
| Вложенный фон | R = max(0, R родителя - отступ) | Концентрические углы, без произвольного радиуса |
| Мелкая предметная плитка, OTP, токен формулы | R = 16 | Дискретная ячейка, не основное действие |

Обычные кнопки и поля имеют высоту 48 px. Для длинных подписей и увеличенного текста есть роль multiline: минимум 48 px при обычном размере текста, автоматическая высота, перенос подписи и тот же радиус control. В billing эта роль действует также в ошибках и диалоге отмены; остальные default/icon не меняются. Компактная роль 44 px предназначена для инструментов шапки; экран не выбирает произвольный размер. Button применяет размер после внешнего className, cn понимает семантические радиусы. AST guard и runtime-тесты подключены к npm run lint: запрещают локальные переопределения, inline style и расширение списка размеров без контракта.

Числа геометрии и классы живут в config/layout.ts и существующей теме globals.css; компоненты читают роль. Соседство само по себе не основание для равного радиуса: сравниваем элементы одного уровня/назначения. У прогресса и кнопки единое правило капсулы, но абсолютный радиус зависит от высоты. У карточки задания другой радиус по роли.

Основное действие чёрное; вторичное нейтральное или с тонкой рамкой. Состояния: focus с видимым кольцом, pressed через transform, disabled сохраняет геометрию, loading не меняет ширину, результат содержит текст/иконку кроме цвета. Шрифт и начертание из действующей typography; поля не меньше 16 px. Отступы сохраняют текущий ритм 4/8/12/16/24, одинаковые отношения имеют одинаковый интервал.

Колокольчик напоминаний остаётся на мягкой квадратной плашке R24: это иллюстрация, а не кнопка. Круглая форма зарезервирована для самостоятельного действия с иконкой. Размер плашки не определяет размер кнопок.

## Пять исправлений

1. Шапка онбординга: три колонки `44 / остаток / 44`, прогресс по центру оболочки, справа пустой неинтерактивный слот
2. Нижняя строка решения: стрелка / растягиваемый ответ / стрелка, одинаковая высота 48. На последнем задании правая стрелка заменяется двойной галочкой с доступным именем «К проверке». Аналогичное поведение у тренировки
3. Прикрепление и ввод занимают одну и ту же центральную колонку. Подписи «Прикрепить» и «Заменить» помещаются в одну строку на 320 px. Длинное действие сначала сокращаем без потери смысла, затем проверяем на минимальной ширине; не уменьшаем шрифт и не добавляем локальный размер кнопки
4. Ответ первой части: знаковое целое или конечная десятичная запись, запятая и точка допустимы. Пустота, минус и незавершённая дробь допустимы только как черновик. Буквы, SQL, экспонента, hex, слеш, второй разделитель не становятся ответом. В storefront ошибка объясняется внутри капсулы: короткий hint и сохранённое значение; полный текст доступен скринридеру. Проверка перед оцениванием использует то же правило, включая старые сохранённые данные. Это UX-валидация, не замена серверной безопасности
5. «Решать» одним нажатием ведёт к первому заданию, ответы продолжаемой попытки сохраняются. Во время перехода понятное ожидание, повторный запуск блокируется. Статус отражает фактический вход в попытку

## Проверки до реализации

Геометрию проверяем в настоящем браузере через getBoundingClientRect и getComputedStyle, не через jsdom и не поиском строк CSS. Допуск 1 CSS px учитывает дробный layout. CSS радиус 9999 px нормализуется по размеру элемента: сравниваем фактическую форму, а не строку.

| ID | Проверяемый результат |
| --- | --- |
| G1 | Центр прогресса совпадает с центром шапки; левый/правый зазор равны |
| G2 | У видимых контролов строки одинаковые top, bottom и height, включая задание 19 |
| G3 | Эффективный радиус действий/поля равен половине высоты, у иконок width = height |
| G4 | Нет горизонтального overflow, контролы внутри viewport и над safe-area; текст не обрезан |
| G5 | Карточки одной роли используют один токен; вложенные углы зависят от padding |
| B1 | Таблица допустимых/недопустимых ответов; вставка, удаление, минус, запятая, старое сохранённое значение |
| B2 | Один клик «Решать» открывает первое задание; повторный клик не создаёт новую попытку |
| B3 | Двойная галочка открывает обзор, прикрепление и ответ сохраняются |

Матрица браузера: 320×640, 375×812, 430×900, 812×375, 1280×900; светлая/тёмная тема, reduced motion, клавиатура и увеличение текста. Репрезентативные экраны: напоминания, выбор онбординга, вход, главная, задачи, квизы, профиль, настройки, пробники, решение 1/13/19, обзор и шторка. Общие примитивы мигрируют целиком. Новые зависимости не нужны для unit-тестов: Node test + установленный TypeScript. Браузерные контракты запускаются через доступный браузерный инструмент; самостоятельный CI-runner потребует отдельно согласованного инструментария.

Сначала сохраняем реальные падения, затем исправляем и повторяем те же проверки. Скриншоты дополняют геометрию, визуальное качество и движение проверяем глазами. Нельзя назвать работу завершённой только по зелёным числовым тестам.
